# 🔄 Subscription Payment System - How It Works

## Overview
The subscription payment system processes recurring payments for customers based on their payment schedules. Here's a comprehensive breakdown of how it works and which IDs are used for successive monthly payments.

## 🎯 Key ID Used for Recurring Payments

### **Primary ID: `afs_registration_id`**
- **This is the crucial ID used for all successive monthly payments**
- Generated by AFS (Payment Gateway) after the first successful payment
- Stored in `Vzat_Recurring_Data` collection under field `afs_registration_id`
- Acts as a token representing the customer's payment method (card)

### Supporting IDs:
- **quotepaymentId**: Business identifier for the subscription (used for tracking/lookup)
- **merchantTransactionId**: Unique ID for each individual payment transaction

## 🔄 Subscription Workflow

### Phase 1: Initial Subscription Setup

1. **Customer initiates subscription payment**
   ```javascript
   // In PostVzatRecurringData.js
   afsData.append('paymentType', 'DB');           // Direct debit for first payment
   afsData.append('recurringType', 'INITIAL');    // Mark as initial subscription
   afsData.append('merchantTransactionId', quotepaymentId);
   ```

2. **Customer completes payment on AFS payment form**
   - Enters credit/debit card details
   - AFS processes the first payment
   - AFS creates a `registrationId` (token) for future payments

3. **AFS sends webhook with registration ID**
   ```javascript
   // SubscriptionController.js - handleAFSWebhook
   if (paymentType === 'PA' && result.code.startsWith('000.')) {
     await Vzat_Recurring_Data.findByIdAndUpdate(subscriptionRecord._id, {
       subscription_status: 'active',
       afs_registration_id: registrationId,  // 🎯 THIS IS THE KEY!
       payments_completed: 1,
       last_payment_date: new Date(timestamp)
     });
   }
   ```

4. **Subscription becomes active**
   - Status changed to 'active'
   - `afs_registration_id` stored for future payments
   - Next payment date calculated and scheduled

### Phase 2: Recurring Monthly Payments

#### Cron Job Processing (Daily at 9:00 AM Dubai time)

1. **Find due subscriptions**
   ```javascript
   // Find subscriptions due today
   const dueSubscriptions = await Vzat_Recurring_Data.find({
     subscription_status: 'active',
     next_charge_date: { $gte: today, $lt: tomorrow },
     $expr: { $lt: ['$payments_completed', '$InstallmentLeft'] }
   });
   ```

2. **Process each subscription payment**
   ```javascript
   // processSubscriptionPayment function
   async function processSubscriptionPayment(subscription) {
     if (!subscription.afs_registration_id) {
       throw new Error('No registration ID found for subscription');
     }
     
     // Use the registration ID for recurring payment
     afsData.append('recurringType', 'REPEATED');
     afsData.append('registrationId', subscription.afs_registration_id); // 🎯 KEY!
     afsData.append('paymentType', 'DB');
     afsData.append('merchantTransactionId', `${subscription.quotepaymentId}_${subscription.payments_completed + 1}`);
   }
   ```

3. **AFS processes payment using stored card token**
   - No customer interaction required
   - Uses the `afs_registration_id` to charge the stored payment method
   - Sends webhook with payment result

4. **Update subscription record**
   ```javascript
   // After successful payment
   const updatedRecord = await Vzat_Recurring_Data.findByIdAndUpdate(
     subscriptionRecord._id,
     {
       $inc: { payments_completed: 1 },
       last_payment_date: new Date(timestamp)
     }
   );
   ```

## 🗄️ Database Structure

### Vzat_Recurring_Data Collection (Main Subscription Record)
```javascript
{
  quotepaymentId: "VZ_123456",              // Business identifier
  afs_registration_id: "reg_abc123def",     // 🎯 TOKEN FOR RECURRING PAYMENTS
  subscription_status: "active",            // active/completed/cancelled
  payments_completed: 3,                    // Number of payments made
  InstallmentLeft: 12,                      // Total installments planned
  Total_After_VAT_Currency: 1800,          // Total subscription amount
  next_charge_date: "2025-09-15",          // When next payment is due
  last_payment_date: "2025-08-15",         // Last successful payment
  Customer_name: "John Doe",
  opp_email: "john@example.com"
}
```

### Payment Flow per Month:
```
Month 1: payments_completed: 0 → 1 (Initial payment with card details)
Month 2: payments_completed: 1 → 2 (Recurring using afs_registration_id)
Month 3: payments_completed: 2 → 3 (Recurring using afs_registration_id)
...
Month 12: payments_completed: 11 → 12 (Final payment, status → 'completed')
```

## 🔐 Security & Card Management

### How Card Changes Work:
1. **New Card Registration**: Creates new `afs_registration_id`
2. **Subscription Update**: 
   ```javascript
   await Vzat_Recurring_Data.findByIdAndUpdate(subscription._id, {
     afs_registration_id: newRegistrationId,  // 🎯 UPDATED TOKEN
     old_registration_id: oldRegistrationId   // Keep old for audit
   });
   ```
3. **Future Payments**: Use the new `afs_registration_id`

### Security Features:
- **No card details stored** - Only registration tokens
- **PCI Compliance** - AFS handles sensitive data
- **Audit Trail** - All changes tracked with timestamps
- **Customer Verification** - Email and subscription ownership validated

## ⏰ Payment Scheduling Logic

### Next Payment Date Calculation:
```javascript
// Calculate next charge date
const currentDate = new Date();
const day = currentDate.getDate();

let chargeDay = day <= 15 ? 10 : 25;  // 10th or 25th of month
let chargeMonth = currentDate.getMonth() + 1;
let chargeYear = currentDate.getFullYear();

if (chargeMonth > 11) {
  chargeMonth = 0;
  chargeYear += 1;
}

const nextChargeDate = new Date(Date.UTC(chargeYear, chargeMonth, chargeDay, 0, 0, 0, 0));
```

### Cron Job Schedule:
- **Frequency**: Daily at 9:00 AM (Asia/Dubai timezone)
- **Logic**: Find subscriptions where `next_charge_date` equals today
- **Duplicate Prevention**: Check `last_processed_date` to avoid re-processing

## 🔍 Payment Tracking

### Individual Payment Identification:
Each recurring payment gets a unique merchant transaction ID:
```javascript
merchantTransactionId: `${quotepaymentId}_${payments_completed + 1}`
// Example: "VZ_123456_3" for the 3rd payment of subscription VZ_123456
```

### Payment Status Tracking:
1. **Webhook Processing**: AFS notifies success/failure
2. **Salesforce Integration**: Payment status sent to CRM
3. **Email Notifications**: Customer and business team notified
4. **Database Updates**: Payment counters and dates updated

## 🚨 Failure Handling

### Payment Failure Scenarios:
1. **Card Expired**: Customer needs to update payment method
2. **Insufficient Funds**: Retry logic can be implemented
3. **Card Cancelled**: Customer must add new payment method
4. **Technical Issues**: Error logging and support notification

### Recovery Process:
```javascript
// Customer can update card using new feature
POST /api/subscription-card/{quotepaymentId}/change-card
// This creates new afs_registration_id for future payments
```

## 🎯 Summary

### **The answer to your question:**
**Successive monthly subscription payments are processed using the `afs_registration_id`** which is:

1. **Generated**: After first successful payment by AFS
2. **Stored**: In `Vzat_Recurring_Data.afs_registration_id` field
3. **Used**: For all recurring payments via AFS `/v1/payments` API
4. **Updated**: When customer changes payment method
5. **Secured**: Token-based, no actual card details stored

This system ensures **secure, automated recurring payments** without storing sensitive card information, while providing customers the flexibility to manage their payment methods through the new card management feature we implemented.
